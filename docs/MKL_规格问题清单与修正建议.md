# MKL 规格问题清单与修正建议（整理版）

> **版本**：0.0.1-alpha
> **配套文档**：《MKL_开发规格书.md》
> **整理原则**：以下问题均按「**保留原功能意图，修正设计/实现**」给出修正方向——**不删除任何功能需求**，只把"做不到/自相矛盾/缺失"的地方修正确。
> **处理方式**：是否执行修正、以及关键技术选型，需用户确认（见文末《需要拍板的决策》）。

## A 类：平台与技术栈矛盾（必须拍板）

### A1. UI 技术栈与"全平台"矛盾
- **位置**：1.3 平台要求 + 3.4 UI 层（QMainWindow/QWidget/QSS）
- **问题**：Qt **Widgets 仅支持桌面**（Windows/macOS/Linux），官方不支持 Android/iOS；QSS 也是 Widgets 特性。按现有设计，Android/iOS 上**根本没有 UI 可运行**。
- **修正方向**：① 统一改用 **Qt Quick（QML）**，一套 UI 覆盖 5 平台，现有 5 个 UI 模块改写为 QML 组件；② 或桌面 Widgets + 移动端 Qt Quick 双 UI（保留现有模块设计，另建移动端页面层）。**不砍任何平台。**

### A2. Windows 7 与 Qt 6 / 新工具链冲突
- **位置**：1.3（Win7 SP1）+ 6.1 CI（windows-2025 构建）
- **问题**：Qt 6 官方**不支持 Windows 7**（最低 Win10 1809+）；VS2022 也不再官方支持 Win7 目标。要在 Win7 运行需 Qt 5.15.2（已 EOL）或自编译旧工具链。
- **修正方向**：主分支 Qt 6 出常规产物，另设 **Qt 5.15.2 + VS2019/MinGW 的 Win7 兼容构建**（CI 增一列）；或全桌面统一 Qt 5.15.2。**不砍 Win7。**

### A3. Linux GLIBC 2.17 与 CI 构建矩阵矛盾
- **位置**：1.3（GLIBC 2.17）+ 6.1（ubuntu-22.04 构建 .AppImage）
- **问题**：Qt 官方二进制基于较新发行版构建（glibc ≥ 2.28 甚至 2.35）；在 Ubuntu 22.04（glibc 2.35）上构建的产物**不可能**在 glibc 2.17 上运行。当前矩阵自相矛盾。
- **修正方向**：在**老容器（如 CentOS 7）内全链自编译**（Qt、OpenSSL、curl），产出真正兼容 2.17 的产物，CI 增加专用构建列；同时 JRE 下载（模块 13 的"GLIBC 兼容"）也需配套 2.17 兼容的 JRE 源。**不砍兼容声明。**

### A4. iOS 上运行 Minecraft Java 版的可行性
- **位置**：1.3（iOS 15.0）+ 1.2 定位
- **问题**：iOS 禁止 JIT，OpenJDK 在 iOS 上无 JIT、性能极差；官方无 iOS 版 JVM，社区方案（PojavLauncher 式）依赖侧载且受 App Store 限制。
- **修正方向**：**保留 iOS 支持**，但明确为"实验性/侧载"定位：iOS 版启动器 + 兼容 JVM 方案调研（AOT/解释执行），验收标准单独放宽，配套 ios_sideload.md 已有基础。**不砍 iOS。**

### A5. Android API 24 与 Qt 最低版本需锁定验证
- **位置**：1.3（Android API 24）
- **问题**：Qt 各版本对最低 Android API 的要求不同（6.2 约 API 21–23，6.5+ 逐步提高），且 API 24 老设备存在 GLES 与分区存储限制；规格未锁定 Qt 版本，兼容性无从验证。
- **修正方向**：锁定 Qt 版本后出具"平台 × Qt 版本兼容性验证表"，必要时调整最低 API 或补充说明。**不砍。**

### A6. 移动端自更新违反商店政策
- **位置**：模块 14 SelfUpdater（全平台自更新）
- **问题**：iOS（App Store）**禁止应用自我更新/替换**；Android 从商店分发的应用同样受限（仅允许 Play 内更新 API）。"全平台自更新"在移动端不可实现。
- **修正方向**：桌面全平台保留完整自更新；移动端修正为「**更新检测 + 跳转商店/侧载页下载**」；更新通道抽象为 `IUpdateChannel`（GitHub / 商店 / 侧载）。**不砍更新功能，只改移动端落地方式。**

## B 类：模块设计缺陷与内部不一致

### B1. `FileUtils::getFileSize` 返回 `std::string` 不合理
- **位置**：模块 3
- **问题**：文件大小是数值，返回字符串无法参与比较/进度计算；与其余数值 API 不一致（若意图是"人类可读"，规格未说明）。
- **修正方向**：返回 `uint64_t`（字节），另提供 `formatFileSize(uint64_t)` 生成可读字符串。**不砍。**

### B2. `StringUtils` 职责与接口不符（JSON 解析缺失）
- **位置**：模块 4
- **问题**：职责写明"JSON 解析"，但接口里没有任何 JSON 方法。
- **修正方向**：在 StringUtils 补充 JSON 解析接口，或新增独立 `JsonUtils` 模块（职责与接口保持一致）。**不砍 JSON 能力。**

### B3. 错误处理类型未定义、策略双轨
- **位置**：2.5 + 模块 9/10/11/13/14 接口
- **问题**：`Result<T>` / `Error` / `ErrorCode` / `LogLevel` 被大量引用但**没有任何模块定义**；2.5 又写"返回 Result 或抛出异常"双轨未定。
- **修正方向**：基础层新增 `Result<T>/Error/ErrorCode`（含文件、函数、行号、系统错误码）与 `LogLevel` 定义；明确全项目统一用 Result 返回（异常仅限不可恢复错误）。

### B4. 同层依赖具体类，违反"同层通过接口通信"
- **位置**：模块 10/11 依赖写"JavaManager"
- **问题**：2.1 规定同层模块通过接口通信，但模块 10/11 依赖具体类 `JavaManager`（模块 9/10/13/14 依赖 `IDownloadService` 是接口，正确）。
- **修正方向**：统一改为依赖 `IJavaManager` / `IDownloadService` 接口。

### B5. ConfigManager 单例 vs 接口原则；`IConfigService` 不存在
- **位置**：模块 7 + 模块 18
- **问题**：ConfigManager 用静态单例 `instance()`，与"模块可替换、接口通信"冲突；模块 18 依赖的 `IConfigService` **在全部 20 个模块中不存在**，且 ConfigManager 属于数据层、UI 依赖的是服务层。
- **修正方向**：新增 `IConfigService` 接口（由 ConfigManager 实现，归属服务层或数据层明确其一），入口层创建后注入；SettingsDialog 依赖 `IConfigService`。**不砍配置功能。**

### B6. `ILogger` 层级标注错误
- **位置**：模块 19 依赖"服务层（ILogger）"
- **问题**：`ILogger` 定义在基础层（模块 1），被标为"服务层依赖"；且实时日志展示需要订阅接口，现有 `log()` 单向接口无法支撑。
- **修正方向**：标注改为"依赖基础层 ILogger（UI 可依赖任意下层，符合依赖规则）"；为 Logger 补充实时订阅（回调/信号）接口。**不砍。**

### B7. AccountStorage"加密"无方案、接口无体现
- **位置**：模块 6
- **问题**：职责含"加密"，但 `save(AccountData)` 接口无加密参数、无方案；跨平台密钥存储差异大（Windows DPAPI / macOS Keychain / Linux libsecret / Android Keystore / iOS Keychain）。
- **修正方向**：新增平台凭证存储抽象 `ICredentialStore`（平台适配层），`save/get` 内部对 token 透明加解密；配置中的 proxyPassword 同样处理。**不砍加密。**

### B8. 下载任务以 url 标识，易失效
- **位置**：模块 12
- **问题**：`addTask` 无返回值，`pause/resume/cancel` 用 url 标识任务；镜像切换后 url 变化、同一 url 多任务都会导致标识失效。
- **修正方向**：`DownloadTask` 增加 `taskId` 字段（或 `addTask` 返回 taskId），所有操作按 taskId；镜像切换不改变任务身份。**不砍。**

### B9. JavaManager 固定 JRE 17，无法覆盖版本需求
- **位置**：模块 13
- **问题**：Minecraft 版本对 Java 要求不同：**1.17 前需 Java 8，1.20.5+ 需 Java 21**，固定只下载 JRE 17 会导致大量版本无法启动。
- **修正方向**：`getOrDownloadJava17` 改为 `getJavaFor(minecraftVersion)`（按版本需求提供 8/17/21 的检测/下载，17 为默认），`hasJava17OrLater` 扩展为按版本判断。**不砍功能，修正为正确能力。**

### B10. LiteLoader 已停更、OptiFine 不是加载器
- **位置**：模块 10
- **问题**：LiteLoader 停更于 1.12.2 时代（1.13+ 无支持）；Quilt 是 Fabric 的分支；**OptiFine 是优化 Mod 而非加载器**，且与 Forge 冲突、安装方式不同（无合并安装）。
- **修正方向**：5 类全部保留，但增加「支持版本范围」元数据（超出范围明确提示并禁用安装）；OptiFine 走独立安装流程（不进入 Forge 合并）。**不砍任何加载器。**

### B11. "网络层（Qt Network）"归属不明
- **位置**：模块 12 依赖
- **问题**：基础层"无依赖"，但网络层既不在 2.2 层级表也不在 2.4 目录规范。
- **修正方向**：明确 Qt Network 为 DownloadService 的**内部实现细节**（不新增层级），或抽 `INetworkClient` 接口供同层复用。

### B12. platform/ 目录不在 5 层结构
- **位置**：2.2 层级表 vs 2.4 目录
- **问题**：目录规范有 `platform/`（平台适配层），层级表却没有这一层；模块 11/13 又依赖"平台适配层"。
- **修正方向**：将 platform/ 明确为「基础层的平台抽象子目录」或提升为独立层次说明，保证层级表与目录、模块依赖一致。

### B13. `InstallProgress.percent` 语义未定义
- **位置**：模块 9
- **问题**：0–1 还是 0–100 未说明。
- **修正方向**：定义为 0–100（float）。

### B14. 游戏启动参数构造细节缺失
- **位置**：模块 11
- **问题**：职责写"构造启动参数"，但 1.13+ 的 `arguments` 与旧版 `minecraftArguments` 格式不同，还需解压 natives、解析 assets 索引、注入 token 参数——规格完全没有这些流程。
- **修正方向**：补「启动参数构造流程」小节：版本 JSON 解析（rules/arguments 替换）→ natives 解压 → assets 索引 → JVM 参数组装 → 新旧格式兼容。

### B15. `UpdateInfo.assets` 键格式未定义
- **位置**：模块 14
- **问题**：`map<platform, url>` 的键格式未定义。
- **修正方向**：定义键格式（如 `"windows-x64"` / `"macos-arm64"`），与 CI 矩阵产物命名对齐。

### B16. Logger 单例与注入未定
- **位置**：模块 1
- **问题**：`Logger` 单例实现但核心模块如何拿到实例未说明；测试替换不便。
- **修正方向**：`Logger::instance()` 提供全局默认，但各模块构造函数接受 `ILogger*` 注入（测试可传 Mock）。建议同时提供 `LOG_*` 宏包装 `file/line` 参数。

### B17. FATAL 弹窗与"基础层无依赖"矛盾
- **位置**：模块 1 完成标准（MKL_FATAL 弹窗最近 50 行）
- **问题**：基础层无依赖原则下，弹窗无法直接调用 UI 库。
- **修正方向**：Logger 内置最近 50 行环形缓冲；弹窗通过平台抽象/回调接口（`IFatalDialogHandler`）由上层注入实现。

### B18. 规范要求 Result，但大量接口返回 bool
- **位置**：2.5 vs 模块 3/6/7
- **问题**：2.5 规定"所有可能失败的操作必须返回 Result<T> 或抛出明确异常"，但 `FileUtils` 全 bool、`IAccountStorage::save/remove` 与 `ConfigManager::save` 也是 bool——自相矛盾。
- **修正方向**：统一策略并写明：**工具类允许 bool + 日志记录**，**数据/服务层必须 Result<T>**（AccountStorage/ConfigManager 改为 Result）。

### B19. `priority` 用 int 魔法数
- **位置**：模块 12 `DownloadTask.priority`（0/1/2）
- **修正方向**：改为枚举 `TaskPriority { HIGH, MEDIUM, LOW }`。

### B20. MainWindow 直接持有 UI 控件类，违反 4.1
- **位置**：模块 15 vs 4.1（UI 模块之间不能互相依赖）
- **问题**：MainWindow 私有成员是 `TitleBar*`、`NavigationBar*` 具体类，正是"UI 模块间直接依赖"。
- **修正方向**：明确「容器例外」规则（MainWindow 作为组装容器允许持有控件，控件之间互不依赖），或控件接口化后注入。二选一并写入规范。

### B21. 服务层接口全同步阻塞
- **位置**：模块 8/9/13/14
- **问题**：`fetchVersionList`、`install`、`detectSystemJava`、`checkForUpdates` 均为同步阻塞调用，UI 线程直接调用会卡死界面。
- **修正方向**：接口异步化设计（回调/信号/任务队列），UI 层通过回调刷新；同步实现仅限内部与测试。

## C 类：功能缺口（规格承诺了但没设计）

> 按"不砍功能"原则，这些承诺必须补上设计，而不是删除。

### C1. 插件系统没有模块
- **位置**：1.2 定位（全平台插件系统）+ 2.4 目录（plugin/）+ 交付物（.mklplugin 示例）
- **问题**：这是核心卖点之一，但 20 个模块中**没有插件系统模块**，.mklplugin 打包格式、插件 API、加载机制全部未定义。
- **修正方向**：新增模块：`PluginManager`（扫描/加载/启停/卸载）、`PluginAPI`（暴露给插件的接口）、`.mklplugin` 格式规范（清单 JSON + 资源 + 原生库）；示例插件作为交付物。

### C2. 账户登录认证服务缺失
- **位置**：模块 5/6
- **问题**：有 `AccountData`（含 Microsoft token/refreshToken）与存储，但**没有任何登录/认证模块**（微软 OAuth 设备码流程、token 刷新、离线账户创建）。
- **修正方向**：新增 `AuthService` 模块（微软 OAuth 设备码登录、token 自动刷新、离线账户），UI 配套登录界面（账户菜单入口已在模块 17）。

### C3. 6 个页面只有 2 个页面模块
- **位置**：4.2 PageType（Home/VersionManager/ModManager/DownloadCenter/LogViewer/Settings）
- **问题**：页面枚举有 6 项，实际模块只有 LogViewer(19)、SettingsDialog(18)，其余 4 个页面（Home、版本管理、模组管理、下载中心）没有模块；若塞进 MainWindow 内部实现则违反单一职责。
- **修正方向**：新增 4 个页面模块：`HomePage`、`VersionManagerPage`、`ModManagerPage`、`DownloadCenterPage`（依赖服务层接口）。

### C4. 模组管理服务缺失
- **位置**：4.2 ModManager 页面
- **问题**：模组管理页面需要"扫描 mods 目录、识别 Forge/Fabric 模组、启用/禁用、依赖检测"服务，规格无此模块。
- **修正方向**：新增 `ModManagerService`（与版本安装/加载器安装联动）。

### C5. 移动端触控方案没有模块
- **位置**：1.2 定位（移动端完整触控方案）+ 交付物（键盘贴图）
- **问题**：触控是移动端核心需求，但 20 个模块无触控/输入模块；"键盘贴图"资源也没有渲染承载方。
- **修正方向**：新增 `TouchInput` 平台模块（虚拟按键、触控板、键盘贴图渲染、与 TouchUI Mod 联动）。

### C6. "默认布局 JSON"没有布局系统
- **位置**：交付物 6（默认布局 JSON）
- **问题**：布局 JSON 暗示 UI 可自定义/可配置布局，但无布局加载模块。
- **修正方向**：新增 `LayoutManager`（布局 JSON 解析/应用/保存），与 MainWindow 内容区配合；如不想做自定义布局，则明确"布局固定，JSON 仅存初始状态"（仍需定义）。

### C7. i18n 机制缺失
- **位置**：模块 7 `language`（zh_CN/en_US）
- **问题**：有语言配置，无翻译机制，UI 文案无法本地化。
- **修正方向**：引入 Qt 翻译（.ts/.qm）或自建 i18n 模块，配置切换语言时重载。

### C8. 崩溃诊断无细节
- **位置**：模块 11 职责（崩溃诊断）
- **问题**：只写了"崩溃诊断"四个字，无判定与提示流程。
- **修正方向**：补崩溃诊断流程：退出码分类、crash-reports/ 与 hs_err 日志解析、错误提示与上报入口。

### C9. 版本清单来源未定义
- **位置**：模块 8
- **问题**：版本列表从哪拉取（URL、协议、缓存策略）未定义。
- **修正方向**：明确 Mojang piston-meta `version_manifest_v2.json` 与镜像（BMCLAPI 等）地址，以及 `mirrors` 配置的语义。
